# Данные о полётах (XContest)

В этой директории содержатся исторические данные о полётах на парапланах, полученные с платформы XContest.

## Источники

Два формата, оба от XContest:

1. **`2006-2026.flights/extract/`** — основной источник (загружается через
   `flight_parsing.load_world_flights`). Мировой экспорт: 5 037 715 полётов,
   партиции `{YYYY}/{CC}-{YYYY}-{MM}.json`. Структура описана ниже.
2. **`xcontest_flights_{region}-{year}.json`** — устаревший (`load_flights_to_dataframe`).
   Только Австрия, только май-сентябрь. Мировой экспорт — его строгое надмножество:
   99.96% записей нашлись, `distance`/`points` совпадают на 99.98%.

Мировой экспорт даёт то, чего в старом формате не было:

* **Координаты на каждый полёт**, а не по каталогу стартов. 3.5M уникальных пар на
  6 874 сайта, разброс внутри старта — медиана 0.23 км. Старый формат давал одну
  точку на сайт (regex по `takeoff.link`).
* **Круглый год.** В альпийских ячейках апрель даёт больше полётов ≥50 км, чем июль,
  а март — больше, чем сентябрь. Именно поэтому сезонное окно расширено до
  1 марта — 31 октября (`dataset_builder.SEASON_START/SEASON_END`).
* **Весь мир**, а не одна страна.

Чего в нём **нет**: `glider.*` (класс крыла), `id`/`ident`, `type`, `countries`.
Фильтр по классу крыла на этих данных не построить — но и не использовался: модель
никогда не читала эти поля, старый лоадер лишь разбирал их «на будущее». Идея из
раздела ниже (исключать полёты на CCC) на новом источнике нереализуема.

### Структура записи мирового экспорта

```jsonc
{
  "startTime": "2024-07-01T14:00:06Z",   // UTC, фактический старт
  "duration": 992,                        // СЕКУНДЫ (в старом формате — ISO8601)
  "takeoff": { "id": 892, "name": "Sonchaux", "countryIso": "CH",
               "lat": 46.41875, "lon": 6.95075 },
  "route":   { "type": "FREE_FLIGHT", "distance": 6.001, "points": 6,
               "factor": 1, "avgSpeed": 27.45 },
  "pilot":   { "id": 24881, "username": "...", "countryIso": "CH" }
}
```

`load_world_flights(clean=True)` отбрасывает мусор источника: точные дубли
(pilot + startTime + distance, ~0.25% строк), нулевые и абсурдные дистанции
(есть запись на 25 511 км), невозможные путевые скорости. Фильтрация по качеству
XC (`min_xc_points`) остаётся за вызывающим кодом.

Оговорка для расширения за пределы Европы: якорь 06/12/18 UTC — альпийский.
Медиана времени старта по UTC: Альпы 11, Индия 5, Япония и Австралия 1,
Колумбия и Мексика 15-17. Для этих регионов нужен пересчёт на локальное
солнечное время и локальную дату.

## Формат файлов (устаревший источник)

Файлы имеют название в формате `xcontest_flights_{region}-{year}.json`.
Примеры:
- `xcontest_flights_it-25.json`: Италия, 2025 год.
- `xcontest_flights_ru-24.json`: Россия, 2024 год.

## Структура объекта полета

Каждый файл содержит массив JSON-объектов. Основные поля:

### Идентификация и Время
*   `id` (int): Уникальный ID полета в системе.
*   `ident` (str): Строковый ID (`Pilot/Date/Time`).
*   `timeClaim` (ISO8601): Время загрузки трека.
*   `pointStart.time` (ISO8601): **Фактическое время старта**. Критически важно для модели.
*   `stats.duration` (ISO8601 Duration): Длительность полета (например, `PT00H12M26S`).

### География и Маршрут
*   `countries` (list[str]): Коды стран пролета.
*   `league.route.distance` (float): Дистанция полета в км.
*   `league.route.points` (float): Очки за полет.
*   `takeoff` (object): Информация о месте старта.
    *   `name`: Название старта (например, "Monte Alpo").
    *   `link`: Ссылка, содержащая **координаты старта**.
        *   Пример: `...filter[point]=10.575997 45.809888...`
        *   Формат: `LON LAT`.

### Пилот и Оборудование
*   `pilot` (object): Данные пилота (имя, пол, страна).
*   `glider` (object): Данные о крыле.
    *   `name`: Модель крыла (например, "SKYWALK Masala 3").
    *   `class`: Класс сертификации (A, B, C, D, CCC). Важно для фильтрации (например, исключать полеты профи на CCC, если целевая аудитория - любители).

## Подготовка данных (ETL)

Для использования в ML-модели необходимо выполнить препроцессинг:

1.  **Парсинг координат:** Извлечь долготу и широту из поля `takeoff.link` (regex по `filter\[point\]=([\d\.]+) ([\d\.]+)`).
2.  **Гео-хэширование:** Привязать координаты старта к BBox ячейке погодной сетки.
3.  **Агрегация:**
    *   Группировка по `(Date, CellID)`.
    *   Target = 1, если есть хотя бы N полетов с дистанцией > X км.
    *   Target = 0, если полетов нет, но погода была (нужна стратегия Negative Sampling).
